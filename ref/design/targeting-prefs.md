# 药水各自的目标偏好（targeting-prefs，2026-10-22）

分支 `claude/targeting-prefs-bc8ea8`。不加攻击距离：每种药水照旧打全场，但各自挑自己最合适的那个敌人。
代码在 `src/sim/targetPick.ts`（测试 `targetPick.test.ts`），`shots.ts` 每 tick 建一个 `TargetPick`，
每条规则只在那一 tick 有对应药水出手时才算一次。REPLAY_VERSION 3 → 4（旧回放不再能重放）。

## 规则

| 药水 | 打谁 | 找不到时 |
|---|---|---|
| 奥术 arcane | 最前面的（离墙最近），多发弹打后面几个，和以前一样 | — |
| 火 fire | 爆炸半径内其他敌人最多的那个（最密的一团） | 最前面 |
| 冰 ice | 还没被减速/冻住、速度最快的；同一 tick 第二个冰瓶换下一个 | 最前面 |
| 闪电 lightning | 前 12 个里，按 hits.ts 的跳法能跳最多次的，取最前的那个 | 最前面 |
| 毒 poison | 最前面一个还没中毒的；同一 tick 第二个毒瓶换下一个 | 最前面 |
| 风 wind | 飞行者 / 绕行者（风能抓住的） | 最前面 |

**墙前优先**：最前面的敌人已贴墙，或离墙不到 `targeting.wallNear`（80 世界单位）时，除风以外所有药水都先打它。
只看画面里的敌人（已越过上边缘）；打平时按敌人上场顺序取先来的。全程整数，没有 Math.random / Date。

开销：每 tick 一次「前排排序」（以前也要做）；火是 O(n²) 但每 tick 只算一次；闪电最多试 12 个起点；
冰、毒的「已瞄准」集合按种类懒建一次。

## 回调

试了 A–K 十来组（只砍火、整体乘系数、按胜率对齐、按经济对齐）。单一系数修不平形状：
不管系数多少，第 8、15 关一带总比以前容易约 20 个点，因为中段敌群最密、火收益最大。
最后按**经济（休闲玩家天数）对齐**选了 J：

| 数值 | 以前 | 现在 | 倍数 |
|---|---|---|---|
| fire.damage | 16 | 8.8 | ×0.55 |
| ice.damage | 14 | 11.9 | ×0.85 |
| lightning.damage | 13 | 11.05 | ×0.85 |
| poison.damage / poisonDps | 7.5 / 16.5 | 3.75 / 8.25 | ×0.5 |
| arcane、wind | 不变 | 不变 | |
| stageHpScale 3 / 4 | — | 1.03 / 1.05 | 新增 |

第 3、4 关加一点血：只砍伤害后 balance-targets 的「第 3 关明显比第 1 关难」不过（0.70）；
1.06 / 1.10 又把 early 守卫的 b0 s3 压到 50（钉 70），取中间 1.03 / 1.05 两边都过。
