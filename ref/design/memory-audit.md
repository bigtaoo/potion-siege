# 内存与每帧开销检查（Potion Siege）

检查日期：2026-10-22 · 分支 `claude/memory-perf-a5be60` · 参照 standing 的 6c87faa / bc6878e / 4bb561a / 639488b

## 怎么测

`npm run memruns -- [局数=12] [速度=8]`（scripts/memRuns.mjs + scripts/cdp.mjs）：

- 起 dev 服务器（端口 5299），用无头 Chrome 打开 `?autoplay&speed=8`，手机尺寸 430×932。
- 连打 12 局，每第三局是无尽模式。每局开始前先把主页的每个页签（药水、工坊、图鉴、商店、战斗）和两个面板（任务、设置）各建一遍，模拟玩家回主页再开局。
- 每局结束后强制 GC 两次，记录：JS 堆、活着的 Graphics / GraphicsContext / Text / Sprite / 所有显示对象（CDP `queryObjects` 按原型计数）、舞台上的节点数、渲染器里的 GPU 图形上下文、GPU 纹理、文字纹理。
- 最后以 1 倍速打 10 秒，用 `HeapProfiler` 采样分配速率和分配最多的函数。

一个数值局局往上涨就是泄漏；涨到某个高点后不再涨的是对象池（正常）。

## 修了什么

1. **Graphics.destroy 不释放自己的上下文**（src/view/graphicsDestroy.ts，启动时在 app.ts 里打补丁，附测试）。
   Pixi 8.22 的 `Graphics.destroy` 只有在**不带参数**调用时才销毁它自己建的 GraphicsContext。游戏里所有 `destroy({ children: true })` 都带参数：主页重建、侧边面板（每波、每次技能变化重建）、HUD 的 Boss 卡和词缀、结算页、教程、按钮。每个 Graphics 的上下文和渲染器为它保留的 GPU 缓冲都留了下来，要等 Pixi 的闲置清理才走。一局关卡大约留下 500 个。
   补丁让 destroy 不管带不带参数都释放它自己的上下文；共享的上下文（传进来的，或 `clone()` 出来的）不是它自己的，不会动。和 standing 的 6c87faa 同一个问题、同一个修法。
2. **开发版把帧报告和卡顿报告打到控制台**（src/analytics/devPrint.ts，perfReport.ts 调用）。
   游戏本来就有完整的报告：每局结束的 `perf`（帧时间、长任务、堆、纹理数、节点数和它们比开局涨了多少），以及 `anomaly`（卡顿 ≥1 秒、报错、WebGL 丢失）。但开发版里事件只进内存 sink，而且要玩家同意分享后才送，异常过了上限（每种 3 个、总共 8 个）就不再记。现在开发版每条 `perf` 和 `anomaly` 都用 `console.info` 打出来，过了上限也打。正式版和测试里不打。`npm run firstframe` 量的是首帧，和这个不重复。
3. **每帧少量垃圾**（BattleView、fxLayer）：特效列表原地压缩，不再每帧 `filter` 出新数组；城墙血量文字只在数值变化时才拼字符串；城墙重绘的判断键从 `open.map(Number).join('')` 换成位掩码。

## 每帧开销：大头在 Pixi 的即时绘制

修复前后 1 倍速战斗每秒都分配约 155 MB，其中 95% 以上来自 Pixi 自己把 Graphics 重新三角化（`buildLine` 约 37 MB/s、`round` 约 33、`buildSimpleUvs` 约 28、`triangulate` 约 20、`build` 约 10）。原因是战场的 world / under / grid / heroOver / drag / 特效层每帧 `clear()` 后重画，敌人、子弹、血条、格子的线条和圆角每帧都要重新三角化。游戏自己代码里分配最多的一处是 `effects.ts` 的 `gear`（约 0.6 MB/s），其余都在 0.5 MB/s 以下。

所以上面第 3 点的修改测不出差别（156.8 → 153.7 在误差内），只是顺手去掉的浪费。在 60 帧下，这个分配量会让 V8 频繁做小 GC，但这次测试没看到卡顿。要真正降下来，需要把不常变的部分（格子框、金色描边、血条底）改成缓存的 GraphicsContext 或纹理，只画会动的部分。这是渲染结构的改动，不在这次范围内，单独做。

## 检查过、没问题的

- 监听器和 ticker：`app.ticker.add` 只在构造时加一次；window 监听只在启动时加；BattleView 是常驻的，每局 `attach` 重用；autoplay 的 `again()` 也不会叠加 ticker。
- 文字：伤害数字 Text 有对象池（最多 31 个）；`text` 赋相同字符串时 Pixi 直接返回；文字纹理数（`canvasText` 里还活着的）局局不涨。
- 纹理：美术图是静态表；章节背景按章懒加载、不卸载，最多 5 张。

## 另外注意到

- 测试里无尽模式的 autoplay 每次在第 3～4 波、约 70 秒游戏时间就结束了。这和内存无关（修复前后一样），但如果 autoplay 在无尽模式里本该打得更久，值得另外看一下。
